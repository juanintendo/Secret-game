# ART MANIFEST — visual canon

Document ID: `ART-MANIFEST`
Location: `art/ART-MANIFEST.md`
Revision date: 2026-09-08
Authority: entry 4 in the order defined by `docs/canon/CANON-INDEX.md` §2. This file is the **single authority on visual truth**.

> Where a prose description in any canon document disagrees with an image labelled `CANONICAL` here, **the image governs and the prose is corrected.** An image is not canonical because it sits in this folder — status is assigned explicitly, per image, below.
>
> Each entry also records **what the image cannot settle.** Those lines are open questions. Do not close one by inference from a single drawing.
>
> **A generated image is construction evidence, not metrology.** Do not derive a measurement from a drawn grid, ruler or bracket and treat it as a dimension. This rule exists because it was violated once — see entry 11.

## 11. `art/STUDY-mech-scale-footprint-001.png`

- **SHA-256:** `59a96719bfebab4d2977ddff59051a0cf57d5e9e92a7866854f704b403522d8e` · 2,301,137 B · 1536×1024
- **Subject:** Provisional mech scale and footprint study.
- **Intended use:** **Rationale support for testing a broad footprint.** Not a dimension source.
- **Status:** `REFERENCE ONLY` · **Revision:** 2026-09-08

**Why `REFERENCE ONLY` and not canonical.** It labels itself provisional throughout — its title, its `MECH 2×2 — PROVISIONAL` bracket, a `PROVISIONAL DIMENSIONS, SUBJECT TO REVISION` note and a `VALIDATE: doors · cover · pathfinding · camera` strip. It is correct to do so.

**Establishes — as construction evidence.** Mech ≈3.6 m against a pilot ≈1.75 m on a shared vertical ruler, ratio ≈2.05×; the ratio is **drawn**, not merely asserted. The pilot depicted is the cyborg and matches entry 4. A **side orthographic cockpit section** with a **rear-upper-torso top-entry hatch** hinged upward and rearward, and a ghosted **seated pilot volume** upright in the upper torso — a pilot demonstrably fits. A **top-down orthographic silhouette**, the first plan view: broad squared pauldrons that overhang, narrower leg mass.

Two consequences worth carrying forward: **embarking is a climb-from-behind-and-above motion**, an authored animation with real cost; and the cockpit consumes much of the upper-torso volume, constraining where internal hardpoints could go.

**Does not establish — and this is the entry that gave this manifest its opening rule.** Measured against its own drawn grid (cell 83.3 px, from four consecutive clean gridlines), the `MECH 2×2` bracket spans **4.01** squares, the `PILOT 1×1` box **1.39**, and the top-down body **3.83**, while the front elevation gives the mech **≈2.4 m** wide at 205.4 px/m. The legend reads `GRID = 1 m × 1 m (TACTICAL)`. **The sheet's labels, legend and two views do not agree with each other.**

**Do not resolve that by arithmetic.** Ruling: *a generated study is construction evidence, not authoritative metrology.* Four concepts stay separate — **logical kernel cell** (integer, no metres) · **entity footprint in cells** · **Unity `cellSizeMeters`** (configurable presentation) · **decorative grid lines in studies** (no dimensional meaning). **The 2×2 footprint remains an untested hypothesis** and is settled only by the spike, never by this drawing.

**`MARKED FOR REMOVAL`.** The sheet carries a stray **`FOR SCIENTIFIC EDUCATIONAL USE ONLY`** label in its top-right corner — a generation artifact, not project text. Remove it in a **new revision (`-002`)**, together with the misleading grid legend and the `2×2` / `1×1` brackets. **Keep the height ruler; that part was sound.** Log both hashes here when the revision lands.

## Cross-asset findings

**Jacket inheritance is verifiable at design level.** The black rectangular sleeve patch and the cyan-dotted zipper tape appear on the leader's jacket (entries 1, 7) and on the synthetic's (entries 2, 6). Character sheets must carry these markings — they are what makes the inheritance readable to a player rather than merely stated in a document.

**Operator's arm asymmetry is era-independent** — bare ungloved right, sleeved gloved left, in the physical form (entry 1), the hologram (entry 2), the sheet (entry 8) and the construction reference (entry 10). Treat it as an identity marker.

**No shared proportion chart exists.** The sheets were produced at three canvas sizes — 1536×1024, 1438×1094, 1374×1145 — with different guide spacing. **No height relationship between any two characters is established**, except the cyborg-to-mech pair in entry 11. `90S-ANIME-XCOM-CODEX-CLAUDE-BRIEF-001.md` §13.1 requires this chart. Compositing the existing sheets onto one reference is an afternoon's work and needs no new illustration.

**Character source package completeness: roughly 2 of 13 items per character.** Orthographics and hero images exist. Missing for everyone: shared proportion chart, face construction sheet, hair mass sheet, costume topology map, palette and material-ID swatch file, material board, gameplay-camera turnaround, silhouette plates at 128 px and 64 px, motion archetype sheet, provenance record. That is not a criticism — orthographics are the correct first item and they are done. It is a warning against reading "the sheets are in" as "art is ready".

## Maintenance rules

1. Every image in `art/` must have an entry here. An image with no entry has no status and must not be used.
2. Record the SHA-256 at the time of entry. If a file changes its hash changes: re-verify, update the hash **and** the revision date, and state what changed.
2a. **Hash what is committed, not what was sent.** The transfer path can add a C2PA `caBX` provenance chunk to a PNG, which changes the file hash while leaving every pixel identical — see entry 12. When a hash mismatch appears, **decode both files and compare pixel arrays before concluding the image changed.** A metadata chunk is not a content change, but the manifest must still record the hash a reader can actually verify.
3. Never delete a superseded entry. Change its status, name what replaced it, and keep it so the same wrong claim is not made twice.
4. When an entry resolves an open detail, remove that line and add an entry to `docs/canon/CANON-DECISIONS.md`.
5. **Record what an image fails to show as a non-fact, never as an absence.** See entry 12.
6. **Read visual details at magnification** before recording them. Costume boundaries, sleeve and glove terminations, limb-material transitions and digit counts are exactly the class of detail that reduced-scale viewing gets wrong. See entry 8.
7. **Provenance and approval are not yet recorded per asset.** Add an approver and an approval date to each entry before any of these sheets is used to commission modelling.
